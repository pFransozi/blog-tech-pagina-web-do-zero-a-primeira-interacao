# 👩‍🏫 Notas para condução da atividade

Este arquivo é para quem está conduzindo a aula.

## Princípio da sequência

A atividade foi desenhada para reduzir carga cognitiva:

```text
uma mudança pequena
→ commit
→ observar no Pages
→ nova mudança
```

O estudante não precisa aprender CLI, instalação do Git ou configuração de VS Code.

## Fluxo usado

```text
GitHub.com
→ github.dev
→ Commit & Push
→ GitHub Pages
```

O `github.dev` funciona no navegador e não oferece terminal ou ambiente de execução. Por isso, o GitHub Pages funciona como o ambiente de visualização do projeto.

## Organização sugerida da aula

### Bloco 1 — Ambientação
- criar repositório;
- abrir `github.dev`;
- criar `index.html`;
- primeiro commit;
- ativar Pages.

### Bloco 2 — HTML e CSS
- estrutura HTML;
- post semântico;
- CSS;
- imagem;
- Flexbox.

### Bloco 3 — JavaScript
- primeiro botão;
- vários botões;
- vários posts.

### Bloco 4 — Organização
- separar `style.css`;
- separar `script.js`;
- personalizar;
- conferir histórico de commits e Pages.

## Apoio operacional

O estudante deve usar o material externo:

https://pfransozi.github.io/github-guia-consulta-rapida-em/

A ideia é não duplicar no projeto todas as telas de GitHub. Este repositório concentra o **código e a progressão do projeto**.

## Observações práticas

- O estudante precisa estar autenticado no GitHub para usar `github.dev`.
- O atalho `.` pode variar conforme teclado/navegador; a alternativa é trocar `github.com` por `github.dev`.
- O trabalho não confirmado fica no armazenamento do navegador. Incentive commits frequentes.
- Em GitHub Pages, publique a branch `main` a partir de `/(root)`.
- A publicação pode levar alguns minutos após o push.

## Resultado conceitual esperado

Ao final, o estudante deve conseguir explicar:

- o repositório guarda o projeto;
- o `github.dev` é usado para editar;
- o commit registra uma versão;
- o push envia a versão ao GitHub;
- o GitHub Pages publica os arquivos do projeto;
- HTML, CSS e JavaScript têm responsabilidades diferentes.
